SPECIAL SECTION: HOW THE OFFLINE SYSTEM WORKS & HOW TO PROVE IT TO JUDGES LIVE
========================================================================================
QUESTION: "Have we integrated an offline system, and can we test it offline in front of judges?"
ANSWER: YES, 100% YES! 
POLARIS is explicitly engineered as an "Edge-Native, Local-First Application" with an 
RFC 9171 Delay-Tolerant Networking (DTN) Engine.

HOW THE OFFLINE ARCHITECTURE WORKS:
1. Zero Cloud Dependency:
   The backend server (Node.js/Express) and client app (React 18/TypeScript/Leaflet) run 
   physically on your local machine (which simulates the on-station Edge Server inside 
   Maitri or Bharati Base).
2. Local Network Operation:
   In Antarctica, personnel access POLARIS via local base Wi-Fi or LAN. No connection 
   to the global internet is required. All HTML, JS, CSS, and tactical maps are served 
   locally from the compiled production bundle.
3. RFC 9171 DTN Asynchronous Queue:
   When in offline mode, any action you perform (logging new cargo, checking out a sortie, 
   updating life support, or triggering emergency SAR) does NOT fail with a network error. 
   Instead, it is instantly written to local storage and appended into the atomic 
   DTN Satellite Queue ('syncQueue').
4. The 32-Byte Packet Burst:
   When satellite connectivity is restored (or when a satellite pass occurs), the DTN 
   engine compresses pending state diffs into compact 32-byte binary bursts and transmits 
   them to the server (/api/sync/dtn-burst) to synchronize with Goa HQ.
